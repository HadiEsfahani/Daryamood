# راه‌اندازی اتصال به Supabase

این پروژه از سه فایل تشکیل شده:

- `index.html` — سایت اصلی (کارت‌های خارجی + نمای تمام‌صفحه‌ی کارت‌های داخلی)
- `admin.html` — پنل مدیریتی که با آن کارت‌های داخلی هر بخش (انرژی / کنترل کیفیت) را اضافه، ویرایش و حذف می‌کنی
- همین فایل راهنما

آدرس پروژه و کلید anon از قبل داخل هر دو فایل (`index.html` و `admin.html`) قرار داده شده:

```
SUPABASE_URL   = https://zxweroyalcsrdejgirmr.supabase.co
SUPABASE_ANON_KEY = (already embedded in both files)
```

کلید anon یک کلید عمومی است و طبیعتاً داخل کد سمت کاربر (Frontend) دیده می‌شود — این مشکلی نیست، امنیت واقعی با تنظیمات RLS (Row Level Security) که در ادامه می‌سازیم تأمین می‌شود: خواندن اطلاعات برای همه آزاد است، ولی نوشتن/ویرایش/حذف فقط برای کاربر لاگین‌شده (خودت در admin.html) ممکن است.

برای راه‌اندازی کامل، این ۴ مرحله را طی کن:

## ۱. ساخت جدول کارت‌های داخلی

وارد پنل Supabase پروژه‌ات شو → منوی **SQL Editor** → یک Query جدید بساز و این اسکریپت را اجرا کن:

```sql
create extension if not exists "pgcrypto";

create table if not exists inner_cards (
  id uuid primary key default gen_random_uuid(),
  section text not null check (section in ('energy', 'quality')),
  position integer not null default 0,
  title text not null default 'کارت جدید',
  category_tag text,
  bullets jsonb not null default '[]'::jsonb,
  expert_name text,
  expert_title text,
  expert_bio text,
  provinces text,
  created_at timestamptz not null default now()
);

alter table inner_cards enable row level security;

-- خواندن برای همه (سایت عمومی باید بتواند کارت‌ها را نمایش دهد)
create policy "public can read inner_cards"
on inner_cards for select
using (true);

-- نوشتن/ویرایش/حذف فقط برای کاربر لاگین‌شده (پنل مدیریت)
create policy "authenticated can insert inner_cards"
on inner_cards for insert
to authenticated
with check (true);

create policy "authenticated can update inner_cards"
on inner_cards for update
to authenticated
using (true)
with check (true);

create policy "authenticated can delete inner_cards"
on inner_cards for delete
to authenticated
using (true);
```

اگر جدول `collaboration_requests` (فرم «همکاری با ما») را قبلاً نساخته‌ای، این را هم اجرا کن:

```sql
create table if not exists collaboration_requests (
  id bigint generated by default as identity primary key,
  created_at timestamptz default now(),
  name text not null,
  email text not null,
  phone text not null,
  field text not null,
  service text
);

alter table collaboration_requests enable row level security;

create policy "anyone can submit a collaboration request"
on collaboration_requests for insert
to anon, authenticated
with check (true);
```

## ۲. ساخت کاربر مدیر (تنها یوزر پنل ادمین)

1. در پنل Supabase برو به **Authentication → Users**.
2. روی **Add user** بزن (نه Invite — همان "Create new user").
3. یک ایمیل و رمز عبور برای خودت وارد کن (مثلاً `admin@daryamood.com`).
4. مطمئن شو گزینه‌ی **Auto Confirm User** فعال باشد تا نیازی به تأیید ایمیل نباشد.
5. در **Authentication → Providers**، مطمئن شو **Email** فعال است. اگر می‌خواهی کسی جز خودت نتواند در آینده ثبت‌نام کند، در **Authentication → Settings** گزینه‌ی **Allow new users to sign up** را خاموش کن (چون تنها راه ورود به admin.html همین یک کاربر است).

## ۳. تست پنل مدیریت

1. فایل `admin.html` را (کنار `index.html`) روی هاست خودت آپلود کن. بهتر است لینک مستقیم این صفحه در منوی سایت گذاشته نشود؛ فقط خودت آدرسش را (مثلاً `https://yourdomain.com/admin.html`) نگه دار.
2. آن را در مرورگر باز کن، با ایمیل/رمزی که در مرحله ۲ ساختی وارد شو.
3. از تب «بهینه‌سازی مصرف انرژی» یا «کنترل کیفیت»، روی «+ افزودن کارت جدید» بزن، اطلاعات را پر کن (عنوان، بولت‌ها، نام و رزومه کارشناس، استان‌های تحت پوشش) و «ذخیره تغییرات» را بزن.
4. تعداد کارت‌ها محدودیتی ندارد — هرچقدر لازم داری اضافه کن؛ در سایت اصلی خودش سطر‌به‌سطر (هر سطر ۳ کارت) نمایش داده می‌شود.

## ۴. تست سایت اصلی

در `index.html`، روی دکمه‌ی «خدمات و محصولات» (کارت انرژی) یا «لیست خدمات کنترل کیفیت» (کارت کنترل کیفیت) کلیک کن — باید همان کارتی که ساختی را در نمای تمام‌صفحه ببینی. با دکمه‌ی × به حالت سه‌کارتی برمی‌گردی.

---

### نکات امنیتی مهم
- کلید anon همیشه در کد سمت کاربر قابل مشاهده است — این طبیعی و طبق طراحی Supabase است. تا وقتی RLS طبق مرحله ۱ درست تنظیم شده باشد، مشکلی نیست.
- **Service Role Key** را هرگز داخل `index.html` یا `admin.html` قرار نده — آن کلید تمام محدودیت‌های RLS را دور می‌زند و فقط باید سمت سرور (اگر روزی لازم شد) استفاده شود.
- اگر می‌خواهی بعداً کاربر مدیر دوم اضافه کنی، دوباره از **Authentication → Users → Add user** استفاده کن.
